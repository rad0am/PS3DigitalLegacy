# PS3 Digital Legacy

## What this app is

A static website (hosted on GitHub Pages) that lists games and DLC available **only digitally** on the PlayStation 3 PlayStation Store. The store is expected to close (the date is unannounced or uncertain), so the site lets users:

- browse a catalog of such titles (search, filters, sorting),
- add games to a "want to buy" list and mark them as "bought",
- sign in and sync that list across devices,
- see a countdown to the store closure.

This is a fan project, not affiliated with Sony. The site sells nothing; it only informs users what can still be bought and where.

All code, identifiers, comments, docs and commit messages are in **English**.

## Stack

The owner's choices are **Svelte**, **TypeScript** and **Firebase**. Do not propose other frameworks or languages.

- **Svelte** with **TypeScript** (strict mode). Recommended setup: SvelteKit with `adapter-static`; plain Svelte + Vite is acceptable if routing stays trivial. Set `paths.base` to the repo name (GitHub Pages serves the site under `/<repo>/`). Use prerendering or hash routing, because Pages has no SPA fallback.
- **Firebase** (client only, no custom backend): **Authentication** (start with Google Sign-In) and **Firestore**.
- **Deploy:** GitHub Actions, a push to `main` publishes the site.
- Node.js is **not installed yet** on the dev machine (`node`/`npm` not found). Install Node LTS before starting.

## Data: `ps3-digital.json`

Lives in the repo root. It is generated by a script, so do not hand-edit it without a reason. Size is about 10 MB.

Structure: `{ schemaVersion, generatedAt, games: Game[] }`.

As of `2026-11-02`: 892 games, 679 of them with `digitalOnly: true`, about 3,100 DLC in total (324 games have DLC).

`Game` fields:

| Field | Description |
| --- | --- |
| `id` | stable UUID, **the per-user key in localStorage and Firestore, never change it** |
| `title`, `alternativeNames` | name and alternative names (useful for search) |
| `regions` | subset of `NA`, `EU`, `JP` |
| `digitalOnly` | show only `true` by default; `false` means a physical release exists |
| `prices` | array of `{ currency, amount }` in many currencies (USD, PLN, EUR, and more); may be empty |
| `storeStatus` | `available`, `delisted` or `unknown` |
| `trophies` | `{ supported, hasPlatinum }`, plus `psnprofilesUrl` |
| `dlc` | array of `{ id, name, trophies, prices }` |
| `notes` | array of strings, e.g. a note about a disc release inside a collection |
| `igdbId`, `igdbUrl`, `coverPhoto`, `screenshots` | IGDB data and images |
| `genres`, `description`, `developers`, `publishers`, `releaseDate`, `playerPerspectives` | IGDB metadata |

### Implications for the app

- **10 MB is too much to ship as one payload.** At build time, generate a lightweight index (id, title, regions, type, genres, price in PLN/EUR/USD, cover, status, DLC count) and load details (description, screenshots, full DLC list and prices) lazily, per game. Gzip on Pages helps but is not enough.
- Currency is user-selectable with a browser-based default; see "Currency selection".
- Surface `storeStatus: "delisted"` and `"unknown"` clearly, so users know a game may no longer be purchasable.
- Covers and screenshots come from `images.igdb.com`. Load them lazily (`loading="lazy"`) and handle errors with a placeholder. Do not copy them into the repo (copyright).
- Add data validation (JSON Schema, e.g. `ajv`) as a CI step. An invalid file must never reach production.

## Features (MVP)

1. Game list with a result count.
2. Search over title and alternative names.
3. Filters: type (game/DLC), region, genre, price, `storeStatus`, "digital only".
4. Sorting: name, price, release date.
5. Game details: cover, metadata, DLC, prices, links (IGDB, PSNProfiles).
6. User list: `wishlist` / `bought` state per `id`, with a progress indicator ("you own X of Y").
7. Countdown to the store closure.
8. "Buy me a coffee" as a plain link (no third-party widget scripts).
9. Language switcher (English and Polish), see "Internationalization".
10. "PSNProfiles" button on the game details view (and on list items that have a platinum), see "PSNProfiles link".
11. Currency selector with a browser-based default and a USD fallback, see "Currency selection".

Later: sign-in and Firebase sync, export/import of the list as JSON.

## User state: local-first

- A Svelte store persists to `localStorage`. The app works fully without signing in.
- Shape: `{ [gameId]: { status: 'wishlist' | 'bought', updatedAt: number } }`.
- On sign-in, **merge**: union of local and remote entries; on conflict the newer `updatedAt` wins per `gameId`. Never blindly overwrite either side.
- Firestore: one document `users/{uid}` holding a map of games. Rules: read and write only when `request.auth.uid == uid`.
- The Firebase config (`apiKey` etc.) is public by design. Security comes from the rules.
- In the Firebase console, add `<login>.github.io` to Authorized domains.

## Currency selection

Users can choose the currency in which prices are shown. The data has prices in 33 currencies (`prices: { currency, amount }[]`), so the selector offers exactly the currencies that occur in the data. Derive that list at build time; do not hard-code it.

**Default currency:**

1. Saved user choice (`localStorage`, and the Firestore user document when signed in).
2. Otherwise derive it from the browser: take the region from `navigator.languages` (e.g. `pl-PL` -> `PL`, `en-GB` -> `GB`, `de-DE` -> `DE`) and map the region to a currency with a small static region-to-currency table (browsers expose no currency API). Use the first entry in `navigator.languages` that yields a currency present in the data.
3. If nothing matches (no region in the locale, unknown region, currency not in the data), use **USD**.

Eurozone countries map to `EUR`. The table is a plain TypeScript map and must be unit-tested.

**Fallback when a game has no price in the selected currency:**

1. Selected currency.
2. `USD`.
3. `EUR`.
4. Show "price unavailable" (localized).

When a fallback currency is shown, label it explicitly (e.g. "9.99 USD"), never silently mixing currencies in a list. Do not convert between currencies; show only prices that exist in the data.

Data facts that justify the chain (as of `2026-11-02`): 605 of 892 games have prices and 287 have none; USD is missing for 73 of the games that do have prices; only 4 priced games have neither USD nor EUR.

Format amounts with `Intl.NumberFormat` using the active UI locale and the displayed currency. Currency choice is independent of the UI language: a Polish-language user may still pick USD. Treat prices as informational ("last known price"), because the store may close or change prices.

## PSNProfiles link

Each game can show a button linking to its PSNProfiles trophy page, so users can check whether the platinum trophy is still obtainable (for example when online servers are gone or trophies are marked unobtainable there).

- Source field: `psnprofilesUrl`. In the current data 768 of 892 games have it (all on `psnprofiles.com`); 124 have none. Every game with `trophies.hasPlatinum: true` (255 games) has a URL.
- Render the button only when `psnprofilesUrl` is set. Do not show a disabled or broken button for the 124 games without one.
- Give extra prominence to the button when `trophies.hasPlatinum` is `true`, since that is the case the user cares about. Games with `trophies.supported: false` show no trophy info.
- **The app does not determine whether a platinum is obtainable.** It only links to PSNProfiles, which is the source of truth. Do not display claims like "platinum obtainable" or "unobtainable" derived from our data. Wording must be neutral, e.g. "Check platinum status on PSNProfiles".
- Open the link in a new tab with `target="_blank"` and `rel="noopener noreferrer"`. Validate at build time that the URL host is `psnprofiles.com` before rendering.
- The label, tooltip and `aria-label` come from the i18n catalog (both `en` and `pl`). The site name "PSNProfiles" is not translated.
- DLC entries have a `trophies` field but no URL of their own; link DLC trophy checks to the parent game's `psnprofilesUrl`.
- Use a plain link, not an embed or API call. Do not scrape PSNProfiles or copy its content into the repo.

## Internationalization (i18n)

The UI ships in **English (`en`)** and **Polish (`pl`)**. English is the source and fallback language. Design the setup so adding a locale later means adding one message file.

- Use a type-safe i18n library that works with Svelte and static output. Recommended: **Paraglide JS** (tree-shakeable, typed message keys); `svelte-i18n` is an acceptable alternative. Pick one and do not mix.
- **No hard-coded UI strings** in components. Every user-visible string goes through the message catalog (`messages/en.json`, `messages/pl.json`), including `aria-label`s, placeholders, empty states and error messages.
- Locale detection: saved choice in `localStorage` first, then `navigator.language`, then `en`. Provide a language switcher. For signed-in users the choice may also be stored in the user's Firestore document.
- Because the site is static on GitHub Pages, either prerender per-locale routes (`/en/...`, `/pl/...`) or switch locale on the client. Decide when setting up routing and record it in "Open decisions".
- Format numbers, dates, prices and plurals with `Intl` APIs and the active locale. Polish has more than two plural forms, so use ICU/plural rules instead of `count === 1` checks.
- Currency is independent of the UI language; see "Currency selection".
- **Game data is not translated.** Titles, descriptions and genre names from `ps3-digital.json` come from IGDB in English and are displayed as they are. Only the application's own UI text is localized. Genre names used as filter labels may be mapped to translated labels if needed.
- Keep `en.json` and `pl.json` key sets identical. Add a CI check that fails when a key exists in one file and not in the other.

## Store closure countdown

The official date is uncertain (sources conflict). Keep it in a single config field, e.g. `closingDate: string | null`:

- `null`: show "closing date not announced".
- future date: show a countdown in days and hours.
- past date: show a "store closed, this is an archive" state.

Do not enter a date without an official announcement from PlayStation.
